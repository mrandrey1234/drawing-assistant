# Чертежи — локальный помощник технолога

Инструкция и описание состояния проекта на 27 октября 2026 года.

Программа сохраняет чертежи в локальный каталог, распознаёт надписи и предлагает размеры. Технолог проверяет карточку и затем ищет чертежи по размерам, названию и описанию. Поиск выдаёт не больше двух ближайших вариантов.

**Текущее состояние: рабочий локальный прототип.** Загрузка, хранение, редактирование и поиск реализованы. Автоматическое распознавание неполное: OCR может пропускать обозначения, а локальная модель ИИ — добавлять несуществующие размеры. Проверка технологом остаётся необходимым этапом перед использованием данных в работе.

## 1. Запуск

### На этом компьютере

1. Откройте папку **«Чертежи»** на рабочем столе.
2. Дважды нажмите **Запустить.cmd**.
3. Дождитесь окна **«Чертежи • помощник технолога»**.

Python, библиотеки, локальный движок и модель уже подготовлены на этом компьютере. Вход в аккаунт и API-ключ не нужны. После установки работа с чертежами не требует интернета.

**После обновления файлов программы закройте старое окно и запустите её заново.** Уже открытое окно продолжает работать со старой версией кода.

Если программа не появляется или сразу закрывается, посмотрите сообщение в окне запуска. Для ручного запуска из терминала в папке проекта:

~~~powershell
python app.py
~~~

### При переносе на другой компьютер

**Версия из GitHub содержит исходный код, но не содержит `.deps`, базу `data`, загруженные чертежи, движок Ollama и веса модели.** После клонирования установите библиотеки по команде ниже. Папка `data` создаётся при работе программы. Учебные изображения также не публикуются: источник и примеры запросов указаны в `Примеры чертежей/Как проверить.txt`. Без файла подшипника соответствующий тест пропускается.

Для необязательного локального ИИ скачайте архив `ollama-windows-amd64.zip` из официального репозитория Ollama: https://github.com/ollama/ollama/releases. Сохраните его в `local_ai`, затем выполните `python local_ai/unpack_runtime.py` и команду загрузки модели ниже. Скрипт распаковки оставляет CPU-версию движка. Совместимость будущих выпусков Ollama с этим прототипом отдельно не проверена.

Нужны Windows, Python с Tkinter и библиотеки из requirements.txt. На текущем компьютере используется Python 3.14. Перенос папки .deps между разными версиями Python и архитектурами не гарантирует работоспособность.

Установка библиотек в папку проекта:

~~~powershell
python -m pip install --target .deps -r requirements.txt
~~~

Для обычного OCR отдельный Ollama не нужен. Для анализа ИИ нужны движок **local_ai/runtime/ollama.exe** и модель **qwen3-vl:2b-instruct** в папке **local_ai/models**. Если движок уже есть, но модели нет:

~~~powershell
python local_ai/setup_model.py
~~~

Эта команда скачивает модель и требует интернета. Полноценного установщика приложения пока нет. Для переноса программы с библиотеками и моделями нужно несколько гигабайт свободного места.

## 3. Пошаговая работа

### 3.1. Загрузить и проверить чертёж

1. Нажмите **«+ Загрузить чертежи»**.
2. Выберите файлы. Для первого теста удобны PNG из папки **«Примеры чертежей»**.
3. Дождитесь окончания загрузки и распознавания.
4. Выберите чертёж в таблице.
5. Нажмите **«Открыть оригинал»** и сравните его с карточкой.
6. Исправьте название, размеры и распознанный текст. Добавьте материал, серию, обозначение или назначение в описание.
7. После сверки отметьте **«Результат проверен технологом»**.
8. Нажмите **«Сохранить карточку»**.

Статус **«Требует проверки»** после загрузки нормален: технолог ещё не подтвердил сведения. Это не означает, что загрузка обязательно завершилась ошибкой.

### 3.2. Ввести размеры

Разделяйте значения пробелами:

~~~text
200 150 80 60 40 25 20 5 R5 R15 R20 R25
~~~

Значение без единицы считается миллиметрами. Для ручного ввода и поиска поддерживаются, например, **12 см**, **0,12 м**, **25,5 мм**. В записи **120x80x10** все значения считаются миллиметрами.

Если используете сантиметры или метры, указывайте единицу у каждого отдельного значения. Запись **12x8x1 см** не следует использовать: единица в конце не распространяется автоматически на всю цепочку.

**20**, **R20** и **Ø20** означают разные параметры. Сохраняйте обозначения в карточке, но учитывайте: поиск пока сравнивает их числовую часть, см. раздел 5.

### 3.3. Повторить OCR для существующего файла

1. Выберите карточку.
2. Нажмите **«Распознать повторно»**.
3. Дождитесь результата и посмотрите строку **«OCR предлагает»**.
4. Для замены полей новым результатом нажмите **«Взять данные из OCR»**.
5. Проверьте текст и размеры, затем нажмите **«Сохранить карточку»**.

Перед повторным распознаванием программа сохраняет текущую форму. Новые предложения OCR хранятся отдельно. В неподтверждённой карточке автоматически обновляются пустые поля либо поля, совпадающие с предыдущим результатом OCR. Ручные отличающиеся значения и подтверждённые сведения сохраняются. Старый текст, происхождение которого неизвестно программе, также может быть сохранён вместо автоматической замены.

Кнопка **«Взять данные из OCR»** явно заменяет текст и размеры в форме и снимает отметку проверки. Сама эта кнопка не сохраняет форму в базу — после неё нужна **«Сохранить карточку»**.

### 3.4. Использовать локальную модель ИИ

1. Выберите чертёж.
2. Для PDF или TIFF укажите номер в поле **«Лист»**. Для обычного PNG/JPG оставьте **1**.
3. Нажмите **«Локальный ИИ · эксперимент»**. Текущая форма будет сохранена перед анализом.
4. Дождитесь окончания. Обработка на этом компьютере занимает несколько минут.
5. Просмотрите детали, предложенные размеры и неопределённости в отдельном окне.
6. Сверьте предложения с оригиналом. Значения, которых нет в OCR, показаны отдельно; это само по себе не доказывает ни ошибку, ни правильность.
7. Выберите одну деталь или **«Все детали»**.
8. Нажмите **«Применить и сохранить размеры»**, если хотите использовать выбранный список.

Кнопка **заменяет**, а не дополняет прежнее поле размеров. Она сразу сохраняет его в базе, обновляет строку каталога и выделяет изменённое поле. Статус становится **«Требует проверки»**. Название, описание и распознанный текст от этой операции не меняются.

Дополнительно сохранять сами перенесённые размеры не нужно. Если вы вручную меняли другие поля, сохраните их обычной кнопкой. После окончательной проверки отметьте флажок технолога и сохраните карточку.

Кнопка **«Результат ИИ»** открывает сохранённый ответ без нового анализа. Ответ проверочного прогона для загруженного примера **01_Подшипник** уже сохранён.

### 3.5. Найти чертёж

Введите запрос и нажмите **«Найти»** или Enter:

~~~text
подшипник 200 60
фланец 100 25
муфта 100 75
корпус сталь
~~~

Материал найдётся по тексту только тогда, когда он присутствует в названии, описании или распознанном тексте. Кнопка **«Все»** возвращает полный каталог. Оригинал открывается кнопкой или двойным нажатием строки.

**Сохраняйте ручные правки перед переключением карточек, поиском и закрытием программы.** Общего автоматического сохранения каждой введённой буквы пока нет.

## 4. Кнопки и сохранение

| Действие | Результат | Нужно ли затем сохранять карточку |
| --- | --- | --- |
| Ручное изменение поля | Изменяется форма | Да |
| «Взять данные из OCR» | Подставляет текст и размеры в форму | Да |
| «Распознать повторно» | Сохраняет текущую форму; выполняет OCR и хранит новые предложения | Да, если затем вручную меняли или подставляли данные |
| «Локальный ИИ · эксперимент» | Сохраняет форму и отдельный ответ модели | Не для хранения ответа; размеры сами не заменяются |
| «Результат ИИ» | Показывает сохранённый ответ | Нет |
| «Применить и сохранить размеры» | Заменяет и сохраняет размеры; снимает подтверждение | Нет для размеров; да для других правок и нового подтверждения |
| «Сохранить карточку» | Записывает поля формы и статус в базу | Нет |

Раньше перенос размеров ИИ только менял форму. Это исправлено: актуальная кнопка называется **«Применить и сохранить размеры»**. Если в окне старое название или поведение — перезапустите программу.

## 5. Как работает поиск

Поиск — алгоритм сравнения, а не запрос к большой языковой модели.

1. Из запроса выделяются числа и слова. Десятичная запятая приводится к точке, поддерживаемые единицы — к миллиметрам.
2. Числа сравниваются с полем размеров. Если оно пустое, используются числа из распознанного текста.
3. Слова сравниваются с названием, описанием и распознанным текстом по сходству написания.
4. Если есть числа и слова, их веса составляют **80% и 20%** соответственно. Для запроса только с числами используется только числовая оценка; только со словами — словесная.
5. Выводятся максимум два результата с итоговой оценкой **не ниже 25%**.

Для каждого запрошенного числа выбирается ближайшее число карточки. Близость уменьшается линейно с относительным отклонением; при отклонении от 25% вклад этого числа становится нулевым. Оценка нескольких чисел усредняется.

### Ограничения поиска

- Процент — показатель сходства, **не вероятность правильного ответа и не точность OCR**.
- Совпадение всех размеров не обязательно: частично подходящий чертёж тоже может попасть в выдачу.
- Одно число карточки может быть ближайшим сразу к нескольким числам запроса. Количество одинаковых размеров не проверяется.
- **20, R20 и Ø20 численно сравниваются как 20.** Тип размера пока не является строгим ограничением.
- Нет надёжной привязки к длине, ширине, отверстию, виду или конкретной детали. Порядок чисел не описывает их назначение.
- Сходство слов не равно пониманию смысла. Синонимы и переводы вроде «втулка» и bush могут не сопоставляться.
- Если поле размеров заполнено, остальные числа из текста не дополняют его. Неполное поле размеров влияет на выдачу.
- Непроверенные карточки тоже участвуют в поиске; отдельного фильтра «только проверенные» пока нет.
- Сохранённый ответ ИИ сам по себе не индексируется. Для числового поиска нужно применить размеры к карточке.

## 6. Как работает распознавание

### OCR: чтение надписей

Для PDF сначала извлекается текстовый слой. Если текста мало или в нём нет кандидатов размеров, страница переводится в изображение и обрабатывается OCR. Это эвристика: PDF с частичным текстовым слоем иногда может не получить дополнительное распознавание всех нужных обозначений.

Основной движок — **RapidOCR**, который уже является нейросетевым распознавателем текста. Он читает весь лист, четыре увеличенных перекрывающихся фрагмента и варианты с поворотом на 90 и 270 градусов. Используются ограничение разрешения, повышение контраста фрагментов и отбрасывание результатов с низкой оценкой OCR.

**OCR Windows** дополнительно помогает читать русские надписи при наличии подходящего языка. Дополнение ограничено: в текущем коде из него добавляются строки с кириллицей без цифр. Основные размеры извлекаются через RapidOCR.

Далее правила выделяют отдельные числа, числовые цепочки, радиусы и диаметры. Некоторые строки масштаба, стандартов и номера на полях отбрасываются. Правила могут как пропустить настоящий размер, так и принять постороннее число за размер.

### ИИ: анализ изображения

Используется **Qwen3-VL 2B Instruct** через **Ollama**. Модель получает изображение листа и возвращает структурированный ответ с предположениями о деталях и размерах.

Текущая настройка:

- один лист за запрос;
- изображение уменьшается до вписывания в **1280 × 1280 пикселей**;
- в запрашиваемом формате — максимум две детали и восемь записей размеров на деталь;
- краткий список неопределённостей;
- вычисления на процессоре;
- ограничения длины ответа и ожидания; слишком длинный или некорректный ответ может быть отклонён.

Проверка формата выявляет неверные поля, типы и недопустимые числа, но **не доказывает, что число действительно нанесено на чертеже**. Надпись «Размер» в ответе не означает, что система определила именно длину или именно ширину.

Рабочее имя модели — **qwen3-vl:2b-instruct**. Проверенный ранее вариант **qwen3-vl:2b** расходовал лимит генерации на внутренний анализ и не выдавал завершённый итоговый ответ. Возвращать его без отдельной проверки не следует.

### Локальность и скорость

Программа обращается к серверу внутри компьютера: **127.0.0.1:11435**. Запускаемый ею сервер настроен с отключёнными облачными функциями; прокси для запросов с изображениями не используются. При штатной работе этой конфигурации чертежи не отправляются внешнему сервису.

Интернет нужен для скачивания библиотек, движка и моделей при установке. После ответа запрашивается выгрузка модели из памяти; сам сервер может оставаться запущенным.

На проверенном компьютере Windows видит около 7 ГБ оперативной памяти и встроенную AMD Vega 8. При настройке свободно было около 2 ГБ. Тест ИИ занял **246 секунд**, но время не гарантировано: оно зависит от листа, свободной памяти и нагрузки. OCR длинного документа также занимает больше времени, поскольку обрабатываются все страницы.

## 7. Проверка на подшипнике

Использован файл **Примеры чертежей/01_Подшипник.png**. Он содержит корпус и вкладыш подшипника: общий список относится к двум деталям.

| Способ | Наблюдавшийся результат |
| --- | --- |
| Улучшенный OCR | Прочитал 80 R5 R20 150 200 R25 60 R15 40, но пропустил линейные 20, 25, 5 |
| ИИ Instruct | Разделил BODY и BUSH, предложил линейные 20, 25, 5, отсутствовавшие в списке OCR |
| Ошибки ИИ | Добавил неверные Ø20, повторял некоторые размеры, пропустил 150 и не извлёк R5 корректно |
| Время ИИ | 246 секунд в одном проверочном прогоне |

Для этого конкретного листа вручную сверенный список уникальных обозначений:

~~~text
200 150 80 60 40 25 20 5 R5 R15 R20 R25
~~~

Это контрольный пример, а не шаблон для остальных чертежей. В списке не сохраняются расположение, принадлежность каждой надписи и число повторений.

Исходный структурированный ответ: **local_ai/bearing_result.json**. Один пример не даёт статистической оценки точности. Сейчас нельзя утверждать, что ИИ стабильно лучше OCR: он нашёл часть пропусков, но внёс новые ошибки.

## 8. Ошибки и способы решения

| Симптом | Возможная причина | Что делать сейчас |
| --- | --- | --- |
| «Требует проверки» | Нет подтверждения технолога или применены новые размеры ИИ | Сверить данные, отметить проверку, сохранить |
| Пустые или неполные размеры | Мелкие цифры, слабый контраст, рукописный текст, пересечение линий | Открыть оригинал, повторить OCR, при необходимости заполнить вручную |
| Буквы вместо цифр | Похожие символы O/0, I/1; повёрнутые или повреждённые надписи | Исправить по оригиналу |
| Посторонние числа в размерах | Штамп, масштаб, номер листа или неверная детекция | Удалить лишнее из поля и сохранить |
| ИИ добавил несуществующий диаметр | Модель угадывает смысл и путает типы размеров | Не применять весь список вслепую; удалить ошибочные значения |
| Смешались несколько деталей | OCR объединяет текст листа; «Все детали» объединяет предложения ИИ | Выбрать одну деталь или подготовить отдельное изображение |
| ИИ пропустил мелкие размеры | Весь лист уменьшается до 1280 пикселей по большей стороне | Подготовить более читаемое изображение отдельной детали; выделения области внутри программы пока нет |
| ИИ долго отвечает | Работа на процессоре, мало памяти, сложный лист | Дождаться статуса, закрыть ненужные тяжёлые приложения; использовать OCR для обычной работы |
| Ошибка памяти или тайм-аут | Не хватает ресурсов либо обработка слишком долгая | Освободить память, попробовать отдельную деталь; при необходимости использовать OCR и ручную проверку |
| «Ответ модели не поместился» | Исчерпан лимит генерации | Попробовать отдельную деталь; увеличение лимита само по себе не гарантирует решения |
| «Модель ещё не скачана» | Нет нужных весов | При наличии движка запустить python local_ai/setup_model.py с интернетом |
| Не запускается сервер | Нет движка, занят порт, ошибка запуска | Проверить local_ai/runtime/ollama.exe и local_ai/server.log |
| «Взять данные из OCR» не обновило каталог | Данные только подставлены в форму | Нажать «Сохранить карточку» |
| Перенос ИИ не сохраняется в старом окне | Работает версия до исправления | Перезапустить; новая кнопка — «Применить и сохранить размеры» |
| Правки исчезли после выбора другой строки | Ручная форма не была сохранена | Сохранять перед переключением и поиском |
| Повторная загрузка ничего не добавила | Файл с тем же содержимым уже в базе | Открыть существующую карточку и повторить распознавание |
| Поиск не находит ожидаемый файл | Нет нужных чисел/слов, ошибка OCR, слабое сходство | Проверить карточку, начать с одного-двух известных параметров |
| Поиск выдал другой похожий чертёж | Приближённое сравнение не проверяет всю геометрию | Сверить оригинал, уточнить запрос и описание |
| Оригинал не открывается | Нет программы просмотра или файл недоступен | Проверить сохранённый файл и приложение для PDF/изображений |
| DWG/STEP не загружается | Прямой поддержки нет | Экспортировать в PDF или изображение |

**Радиусы и диаметры не эквивалентны линейным размерам с тем же числом.** Если модель предложила Ø20, а на оригинале написано 20 или R20, это ошибка типа параметра.

## 9. Соответствие BPMN

Предоставленная BPMN-модель описывает более широкую систему: от загрузки и распознавания до подбора оборудования и утверждения технологической карты.

Реализована часть процесса:

**Загрузка → чтение надписей → предложения параметров → проверка и исправление технологом → сохранение → поиск чертежа.**

ИИ предлагает разделение на детали и типы размеров, но это ещё не надёжное распознавание геометрических объектов.

Пока отсутствуют:

- авторизация, роли и полноценная многопользовательская работа;
- прямой импорт DWG/STEP и чтение геометрии CAD;
- надёжное выделение контуров, отверстий, пазов, резьбы и фасок;
- связь размера с геометрическим элементом и координатами на листе;
- структурная обработка допусков, посадок, шероховатости и требований;
- отдельные структурированные поля материала, серии и назначения;
- справочники стандартов, материалов, оборудования и инструмента;
- подбор станков, оснастки и режимов обработки;
- построение маршрута, выпуск и утверждение технологической карты;
- встроенная обрезка изображения и наложение найденных размеров на оригинал;
- история версий, отмена изменения размеров, удаление карточки и экспорт каталога через интерфейс;
- автоматическое обучение модели на правках технолога.

Исправление карточки улучшает данные для поиска, но не переобучает OCR или модель ИИ.

## 10. Файлы и резервная копия

| Файл или папка | Назначение |
| --- | --- |
| Запустить.cmd | Запуск |
| app.py | Окно и действия пользователя |
| core.py | Каталог, OCR, извлечение чисел, поиск |
| ocr.ps1 | Вызов OCR Windows |
| local_vision.py | Локальная модель и проверка формата ответа |
| requirements.txt | Основные зависимости Python |
| .deps | Установленные локально библиотеки |
| data/catalog.sqlite3 | Карточки, тексты, размеры, статусы и последний ответ ИИ |
| data/files | Копии оригиналов |
| Примеры чертежей | Учебные изображения, исходный PDF и краткая инструкция |

| local_ai/models | Веса моделей |
| local_ai/server.log | Журнал сервера |
| local_ai/setup_model.py | Загрузка рабочей модели |
| local_ai/check_drawing.py | Реальный тест подшипника; выполняется несколько минут |
| local_ai/bearing_result.json | Ответ проверочного анализа |
| test_*.py | Автоматические проверки |

OCR объединяет многостраничный файл в одну карточку. ИИ анализирует выбранный лист; следующий анализ карточки заменяет её предыдущий ответ ИИ. Истории ответов по всем листам пока нет. Применение размеров одной детали не создаёт отдельную карточку этой детали.

### Резервная копия

1. Дождитесь окончания обработки и закройте программу.
2. Скопируйте **всю папку data** в резервное место.
3. Для полного переноса приложения сохраните также код, зависимости и local_ai либо подготовьте их заново.

Одной копии базы недостаточно для переноса оригиналов. Не удаляйте data/files: исходная папка загрузки не заменяет хранилище каталога.

## 11. Проверки программы

Команды выполняются из папки проекта:

~~~powershell
python -m unittest -v test_core.py
python -m unittest -v test_local_vision.py
python -m unittest -v test_ui_transfer.py
~~~

- **test_core.py:** извлечение размеров, единицы, ранжирование, PDF, дубликаты, сохранение ручных правок и реальное OCR подшипника.
- **test_local_vision.py:** структура ответа, недопустимые значения, номер листа, локальный запрос, сохранность подтверждённых полей. Ответ модели в тесте подключения подменён тестовым: это не измерение точности ИИ.
- **test_ui_transfer.py:** настоящее нажатие кнопки в тестовом окне, применение всех размеров или одной детали, обновление таблицы и сохранение при повторном открытии. Используется временная база.

UI-проверке нужен доступ к рабочему столу Windows. OCR-проверкам нужны библиотеки и примеры. Реальный запуск модели выполняется отдельно:

~~~powershell
python local_ai/check_drawing.py
~~~

Команда анализирует пример и перезаписывает **local_ai/bearing_result.json**. Она не применяет предложенные размеры к пользовательским карточкам.

Программные тесты подтверждают работу проверенных функций, но не правильность распознавания любых новых чертежей. В ходе разработки отдельно проверялись базовые функции, локальное подключение и исправленная кнопка. Статистического испытания на большой коллекции ещё не было.

## 12. План улучшений

Это направления дальнейшей разработки, а не уже доступные функции. Приоритет — сначала сделать данные проверяемыми и поиск точнее, затем расширять автоматизацию.

### Этап 1. Удобная проверка и сохранность правок

- Показывать оригинал рядом с карточкой и подсвечивать место каждого найденного размера.
- Сохранять координаты надписи и оценку OCR; не выдавать эту оценку за гарантию правильности.
- Подтверждать или отклонять каждое предложение ИИ отдельно, вместо замены всего списка.
- Добавить предыдущие версии, отмену и предупреждение о несохранённой форме.
- Добавить прогресс по страницам, отмену долгой операции и восстановление после ошибки.

**Критерий готовности:** применённый размер можно найти на листе, проверить и отменить его изменение.

### Этап 2. Структурированные параметры и строгий поиск

- Хранить значение, единицу, тип, деталь, лист, элемент, допуск, источник и статус проверки отдельно.
- Различать в поиске линейный 20, радиус R20 и диаметр Ø20; учитывать диапазоны и требуемую точность.
- Добавить режимы «точное совпадение» и «ближайшие», фильтры материала, обозначения и проверенных карточек.
- Объяснять выдачу: какие параметры совпали, какие отсутствуют и насколько отличаются.
- Улучшить обработку русских слов, форм слов, синонимов и технических обозначений.

**Критерий готовности:** поиск диаметра не принимает радиус за тот же параметр, а совпадения объяснены пользователю.

### Этап 3. Качество распознавания

- Выделять детали, штамп и размерные надписи до OCR; читать мелкий текст без уменьшения всего листа.
- Исправлять наклон и шум; осторожно отделять линии от текста, проверяя, что цифры не повреждаются.
- Читать векторные надписи и размерные объекты PDF/CAD напрямую, когда они доступны.
- Сопоставлять OCR и визуальную модель по одной области; конфликт отправлять на проверку.
- Сравнивать другие локальные модели на одинаковых примерах. Более крупная модель может требовать больше памяти и ускоритель, но размер сам по себе не гарантирует точность.
- Собирать обезличенный набор чертежей с проверенной разметкой для специализированного обучения. Такое обучение пока не реализовано.

**Критерий готовности:** улучшение подтверждено на независимом наборе, а не на одном знакомом подшипнике.

### Этап 4. Измерение качества и скорости

- Подготовить чистые PDF, сканы, разные шрифты, русские надписи, листы с несколькими деталями и плохим качеством.
- Разметить правильные значения и типы; разделить примеры для настройки и независимой проверки.
- Измерять пропуски, ложные размеры, ошибки типа и единиц, разделение деталей и качество первых двух результатов поиска.
- Замерять время, память и долю неуспешных обработок на реальном компьютере.
- Проверять восстановление после повреждённого файла, отсутствия модели, сбоя установки и закрытия окна.

**Критерий готовности:** воспроизводимый отчёт о качестве и ограничениях каждой версии.

### Этап 5. Полная BPMN-система

После надёжного извлечения и подтверждения параметров можно добавлять роли, справочники материалов и стандартов, оборудование, инструмент, правила подбора операций, технологический маршрут и выпуск технологической карты.

Каждый следующий этап должен использовать проверенные структурированные данные. Ошибка размера не должна автоматически переходить в выбор оборудования или технологическую карту без проверки технологом.
